IDE Synth Bay (formerly HDD Synth Pro) emulates an IDE hard disk and a CD-ROM drive from a microSD card. This release adds a new, experimental way of answering the IDE bus, the **register table**, which makes PIO writes much faster and lets the drive work with hosts that don't wait for its ready signal. It is off unless you turn it on; with it off, the drive behaves as in v0.32.2.

## Which file to flash

Put the board in its bootloader (hold BOOTSEL while plugging it in, or type `b` on the serial console), then copy one UF2 onto the drive that appears.

| File | What it is |
|---|---|
| `hddsynthpro-pcb-drive-v0.33.0.uf2` | The drive for the **IDE Synth Bay PCB**: hard disk, CD-ROM drive or both, the SD card on 4-bit SDIO. |
| `hddsynthpro-bb48-drive-v0.33.0.uf2` | The same for the **Olimex RP2350-PICO2-BB48** (the card on SPI). It also runs on the PCB, more slowly. |
| `hddsynthpro-bb48-listen-v0.33.0.uf2` | Listen only, for recording a real drive's bus; never drives a pin. |

## Added

- **The register table (experimental).** Put `register_table = on` in `HDDSYNTH.INI` to try it. The board's PIO hardware answers every register read itself, within about 30 ns, from a table the firmware keeps up to date, rather than holding the PC on IORDY while the firmware works out the answer. That suits hosts that don't wait for IORDY, and it is faster on those that do.
  - In an Athlon XP PC (PIO 3, the card on SDIO), the benchmark disk wrote at **3.63 MB/s**, against 2.03 with the fastest earlier setting, and read at 4.12 MB/s, about the same as before.
  - Through USB IDE adapters it is the fastest PIO yet: 1.69 MB/s reads and 1.78 writes through a JMicron adapter, 2.40 and 2.65 through an Innostor one. The Innostor checks the drive's status without waiting for IORDY, and no earlier setting worked with it.
  - It serves a hard disk in PIO modes only: no DMA is offered while it runs. With a CD-ROM drive configured, or with `isa = on`, the drive uses its usual way of answering instead, and the console's `S` says why.
- **Advice on the bus program** (`AUTOBUS`): from what it sees after each reset, the drive works out which way of answering would suit the PC it's plugged into, and prints it (`AUTOBUS` lines, `autobus` in `s`). Advice only: nothing switches yet.

## Fixed

- Console `E` could spoil the setting on the last line of `HDDSYNTH.INI` when that line ended in a bare carriage return (a CD image name was ignored).
- `BUSERR` lines no longer print when USB serial has no room, which could hold up the firmware.

## Tested

- The Athlon XP PC with the register table: MS-DOS boots and runs; the benchmark disk passes, with all 81,904 sectors checked right and no BIOS errors; Doom from the CD-ROM drive beside it.
- Through the two USB adapters: the read and write tests and an hour's soak on each (4.0 GB and 6.2 GB, none wrong).
- The other ways of answering the bus measure the same speeds as on v0.32.2.

## Known limits

- Everything in v0.32.2's notes still applies.
- The register table hasn't yet been tried in a PC that ignores IORDY (the Pentium-era PIIX it was designed for), in an ISA PC, or in an Amiga.
- With the register table on, the IORDY diagnostics (`iordy_ignored` and the slow-read timer) aren't measured, and on the PCB the IOCS16# line for ISA cards isn't driven.
