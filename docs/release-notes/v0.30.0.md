HDDSynthPro emulates an IDE hard disk (and now a CD-ROM drive) from a microSD card, on an Olimex RP2350-PICO2-BB48. This release brings everything since v0.28.0: a second drive, a folder served as a disk, a faster bus program, CD-ROM drives (ISO or BIN/CUE), and multiword DMA that works with every bus program.

## Which file to flash

Put the board in its bootloader (hold BOOT while plugging it in, or type `b` on the serial console), then copy one UF2 onto the drive that appears.

| File | What it is |
|---|---|
| `hddsynthpro-bb48-drive-v0.30.0.uf2` | **The hard disk drive.** One or two hard disks (device 0, and optionally device 1). Start here. |
| `hddsynthpro-bb48-hdcd-v0.30.0.uf2` | *Exploratory.* The same, with a **CD-ROM drive as device 1** instead (`device1 = cdrom`): a hard disk and a CD-ROM from one board. |
| `hddsynthpro-bb48-cdrom-v0.30.0.uf2` | *Exploratory.* A **CD-ROM drive** on its own, as device 0. |
| `hddsynthpro-bb48-listen-v0.30.0.uf2` | Listen only, for recording a real drive's bus; never drives a pin. |

## New

- **Two drives.** `device1 = NAME` adds a second drive (device 1, the slave), so a PC sees two hard disks. It can be another image, or a **folder on the card**, served as a read-only FAT16 disk built on the fly (up to 1,024 entries and 2 GB): put files in a folder on your computer and the retro PC reads them as D:. Both an ICL 386 and an Athlon XP found device 1 with their BIOS on auto.
- **CD-ROM drives** (exploratory). An ISO image on the card served as an ATAPI CD-ROM drive: data discs (ISO 9660), PIO or multiword DMA. Doom ran from its CD on an Athlon XP under DOS (MSCDEX), and Windows 11 mounted the same ISO through a USB-IDE adapter. `cdrom = NAME.ISO` picks the disc, or `NAME.CUE` for a BIN/CUE image (its data track; audio tracks are left out); console `M` changes it while the drive runs (`none` ejects).
- **A hard disk and a CD-ROM together** (exploratory, `bb48_hdcd`): `device1 = cdrom` turns device 1 into the CD-ROM drive. Through a USB IDE adapter Windows shows both, mounts ISOs on the CD-ROM and sees discs changed from the console; the hard disk keeps its full DMA speed, and both ran an hour together with every sector checked. With a CD-ROM as device 1 the drive uses its standard bus program (`ide_bus`). *Not yet tried on a retro PC.*
- **The data lane** (`early_answers = off`): data reads answered by PIO and DMA without core 1. The fastest program for PCs whose controller waits for the drive: on an Athlon XP, reads 2.18 MB/s and writes 1.98 MB/s, against 1.78 and 1.24 with early answers. Soaked 400 minutes through a USB adapter: 18.6 GB, no errors, 31.9 million sectors checked on the cable. **Not for 16-bit ISA cards.**
- **Read-only ISOs open**, as files copied off a real CD often are.
- **Clearer welcome disk:** its `README.TXT` lists every setting, with a "which settings for your computer" table.

## Changed

- **Settings renamed:** `image` is now `device0`. Old files still work, and the console's `E` rewrites the old name.

## Fixed

- **Multiword DMA under early answers** took about 12 s per 64 KB read; now 8.8 MB/s reads and 12.5 MB/s writes through a USB adapter.
- A command could be starved by a host polling Status back to back (the drive stayed busy for good).
- The board halted at start-up with a folder as device 1.
- Device 1 naming the same image as device 0 (which would show one filesystem as two disks) is now refused.

## Which settings for which computer

| Computer | Settings |
|---|---|
| 286, 386, or a 486 with a 16-bit ISA IDE card | the defaults, or `isa = on` |
| A PCI controller (Pentium and later) | the defaults |
| ...faster, if the controller waits for the drive | `early_answers = off` (never with an ISA card) |
| A USB-IDE adapter that can do DMA | `dma = on`, or `mode = mdma2` |
| The CD-ROM through a USB-IDE adapter | `mode = mdma2` (adapters may send every packet by DMA) |

DMA has run through a USB adapter (soaked 10 hours), not yet on a retro PC, so it stays off by default.

## Upgrading

Your card's `HDDSYNTH.INI` keeps working. To see the new settings, copy the sample `HDDSYNTH.INI` from the welcome disk (start the drive without a card), or set them from the serial console: `E`, then `key = value` and Enter, then `!` to restart.

## Known limits

- The CD-ROM builds hold some register reads longer than ATA's 1,250 ns (up to 3.6 µs through a USB adapter). PCs that wait for the drive, as every one tried has, don't mind; a diagnostic is in the code for the next round.
- Through a USB IDE adapter that sets the DMA bit on every PACKET command (as the one on the test rig does), the CD-ROM needs multiword DMA offered: `mode = mdma2`.
- The CD-ROM drive serves data only: a BIN/CUE's audio tracks are left out (no CD audio).
- The Amiga 1200 doesn't boot from the drive yet.
- Ultra DMA isn't offered; PIO modes 0-3 and multiword DMA 0-2 are.
