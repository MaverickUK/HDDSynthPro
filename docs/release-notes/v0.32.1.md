IDE Synth Bay (formerly HDD Synth Pro) emulates an IDE hard disk and a CD-ROM drive from a microSD card. This release fixes a rare wrong data word from the CD-ROM drive on PCI PCs. If you serve a CD-ROM to a retro PC, update.

## Which file to flash

Put the board in its bootloader (hold BOOTSEL while plugging it in, or type `b` on the serial console), then copy one UF2 onto the drive that appears.

| File | What it is |
|---|---|
| `hddsynthpro-pcb-drive-v0.32.1.uf2` | The drive for the **IDE Synth Bay PCB**: hard disk, CD-ROM drive or both, the SD card on 4-bit SDIO. |
| `hddsynthpro-bb48-drive-v0.32.1.uf2` | The same for the **Olimex RP2350-PICO2-BB48** (the card on SPI). It also runs on the PCB, more slowly. |
| `hddsynthpro-bb48-listen-v0.32.1.uf2` | Listen only, for recording a real drive's bus; never drives a pin. |

## Fixed

- **A wrong data word from the CD-ROM drive, about one in 2.5 million, on PCI PCs.** With a CD-ROM configured, the drive turned on a safety feature meant only for ISA IDE cards, which stops a stalled ISA cycle from freezing the PC by releasing the IDE bus's IORDY line ("wait") after 23 µs. During fast runs of data reads it sometimes released IORDY in the middle of a read, and the PC then took the word before the drive had put it on the cable. Doom from CD quit after an hour or so with `R_TextureNumForName: ... not found`, a texture name with two letters wrong; other programs could misread a file. The CD-ROM drive now leaves that feature to the `isa` setting.

## Changed

- **With a CD-ROM drive on an ISA IDE card, set `isa = on` in `HDDSYNTH.INI`** (console `E isa = on`, then `!`). Up to v0.32.0 the CD-ROM drive turned it on by itself. PCI PCs and USB adapters want `isa = off`, the default.
- `s` shows `iordy_early_data`, and the console prints an `EARLYDATA` line for each data read that starts before the drive is holding IORDY: normally none.

## Tested

On the IDE Synth Bay PCB in an Athlon XP PC (PIO mode 3, the hard disk as C: and a Doom CD image as D:, from a Windows 98 startup floppy), Doom's demo loop with every sector checked on the IDE cable:
- before the fix, 5 wrong words in 74,600 sectors, over four test builds;
- with it, 82,176 sectors and none wrong, in two runs.

Also: the firmware builds, the core 1 timing checks and the unit and simulation tests.

## Known limits

- Everything in v0.32.0's notes still applies.
- **With `isa = on`** the safety feature can still misjudge a fast run of reads in the same way. ISA PCs have been slow enough not to so far. An improved version is written and passes its simulation tests, but waits for a test on a 386 with an ISA card before it's released.
