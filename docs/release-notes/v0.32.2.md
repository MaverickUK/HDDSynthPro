IDE Synth Bay (formerly HDD Synth Pro) emulates an IDE hard disk and a CD-ROM drive from a microSD card. This release makes the CD-ROM drive answer its status checks faster. With a hard disk alone nothing changes.

## Which file to flash

Put the board in its bootloader (hold BOOTSEL while plugging it in, or type `b` on the serial console), then copy one UF2 onto the drive that appears.

| File | What it is |
|---|---|
| `hddsynthpro-pcb-drive-v0.32.2.uf2` | The drive for the **IDE Synth Bay PCB**: hard disk, CD-ROM drive or both, the SD card on 4-bit SDIO. |
| `hddsynthpro-bb48-drive-v0.32.2.uf2` | The same for the **Olimex RP2350-PICO2-BB48** (the card on SPI). It also runs on the PCB, more slowly. |
| `hddsynthpro-bb48-listen-v0.32.2.uf2` | Listen only, for recording a real drive's bus; never drives a pin. |

## Changed

- **The CD-ROM drive answers status checks faster.** With a CD-ROM configured, each write to the drive's registers cost the firmware about 1.6 µs, so a status check made straight after a few of them was held up to 4.3 µs while the drive caught up. ATA allows 1.25 µs. Writes that can't change anything now take a short path. In an Athlon XP PC under DOS, reading Doom from the CD, status checks held past 1.25 µs went from 1.32 to 0.55 per CD read, and the longest from 4.3 µs to 2.4 µs. PCs that wait for the drive's ready signal, as every one tried so far does, were never misled by them, only slowed a little.
- `s` shows which interrupts the firmware's second core takes (`c1_irq`).

## Tested

- The Athlon XP PC, on the PCB with the card on SDIO: Doom's demo loop from the CD-ROM for 25 minutes: 1,405 CD reads, 20,546 sectors checked on the IDE cable, none wrong, no card dropouts.
- Through a USB IDE adapter: the CD-ROM's read test on both drive files (the whole test disc read back right), the hard disk's read and write tests with the CD-ROM beside it, and an hour of reading the CD-ROM in Doom's pattern with the hard disk between: 498,293 CD reads and 99,935 disk reads, none wrong, 8.4 million sectors checked on the cable, none bad.

## Known limits

- Everything in v0.32.1's notes still applies.
- Some status checks still take longer than ATA's 1.25 µs with a CD-ROM configured, up to about 2.4 µs. Being looked into.
