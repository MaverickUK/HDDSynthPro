HDDSynthPro emulates an IDE hard disk and a CD-ROM drive from a microSD card. This release folds the CD-ROM firmware into the drive firmware: **one file per board** now serves a hard disk, a CD-ROM drive, or both, chosen in `HDDSYNTH.INI`. On the HDDSynthPro PCB the CD-ROM drive gets the fast SD card bus too.

## Which file to flash

Put the board in its bootloader (hold BOOTSEL while plugging it in, or type `b` on the serial console), then copy one UF2 onto the drive that appears.

| File | What it is |
|---|---|
| `hddsynthpro-pcb-drive-v0.32.0.uf2` | The drive for the **HDDSynthPro PCB**: hard disk, CD-ROM drive or both, the SD card on 4-bit SDIO. |
| `hddsynthpro-bb48-drive-v0.32.0.uf2` | The same for the **Olimex RP2350-PICO2-BB48** (the card on SPI). It also runs on the PCB, more slowly. |
| `hddsynthpro-bb48-listen-v0.32.0.uf2` | Listen only, for recording a real drive's bus; never drives a pin. |

The `bb48-cdrom` and `bb48-hdcd` files are gone: their drives are settings now (below).

## New

- **A CD-ROM drive by settings.** In `HDDSYNTH.INI` (console `E` edits it):
  - `device1 = cdrom`: a hard disk as device 0 and a CD-ROM drive as device 1, as the `bb48-hdcd` firmware was;
  - `device0 = cdrom`: a CD-ROM drive alone, as the `bb48-cdrom` firmware was;
  - `cdrom = GAME.ISO` names the disc (an ISO, or a CUE sheet and its BIN); `cdrom = none` serves the built-in test disc. A name ending in `.ISO` or `.CUE` in place of `cdrom` works too, and console `M` changes the disc while the drive runs.

  Settings files from v0.31.0 work unchanged.
- **The CD-ROM on the PCB's fast card bus.** Through a USB IDE adapter, Windows read a whole game CD's files at 6.7 MB/s (the BB48's SPI bus tops out near 1.8).
- **No cost to the hard disk.** With no CD-ROM configured, the drive runs the same hard disk code as v0.31.0, from almost the same place in memory (the CD-ROM's code sits after it): in PIO through a USB adapter it reads at v0.31.0's speed (1.20 MB/s, the adapter's pace) and writes within 2% of it.

## Changed

- With a CD-ROM drive configured, the drive always runs the `ide_bus` bus program, whatever `early_answers` says: on early answers the USB adapter never detected it. `S` says which program runs.
- The serial console's READY line no longer names a build (`READY HDDSynthPro 0.32.0 slice3`); `S` says where the CD-ROM drive is (`CONFIG device0=cdrom kind=cdrom disc=... frames=...`).

## Fixed

- On the PCB, with nothing from the card on device 0 (the test disk, or a CD-ROM with no disc), device 1's image or disc was read through a PIO block the card had only borrowed; a console `S` could take it back. This was so in v0.31.0 too, with `device0 = none` and a `device1` image.

## Known limits

- Everything in v0.31.0's notes still applies, apart from "the CD-ROM builds keep the card on SPI".
- A CD-ROM as device 0 has no device 1 beside it; a hard disk or folder as device 1 needs a hard disk as device 0.
- Some USB IDE adapters send every CD-ROM command by DMA (the test rig's does: it shows as JMicron 152D:2338). Through one of them the CD-ROM drive needs `mode = mdma2` and `dma = on`; without DMA it refuses those commands, and the adapter resets the drive over and over and shows neither drive. Retro PCs send CD-ROM commands by PIO unless their driver chose DMA.
- The USB adapter on the test rig goes silent after the drive restarts with a CD-ROM configured, until it's unplugged and plugged back in. Retro PCs reset the drive themselves at power-on.
