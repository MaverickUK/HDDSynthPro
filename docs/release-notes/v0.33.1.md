IDE Synth Bay (formerly HDD Synth Pro) emulates an IDE hard disk and a CD-ROM drive from a microSD card. This release adds **block mode** (READ MULTIPLE and WRITE MULTIPLE): a PC can move up to 8 sectors per interrupt instead of one, which makes reads about a third faster on the default settings. Most BIOSes turn it on by themselves; there is nothing to set.

## Which file to flash

Put the board in its bootloader (hold BOOTSEL while plugging it in, or type `b` on the serial console), then copy one UF2 onto the drive that appears.

| File | What it is |
|---|---|
| `hddsynthpro-pcb-drive-v0.33.1.uf2` | The drive for the **IDE Synth Bay PCB**: hard disk, CD-ROM drive or both, the SD card on 4-bit SDIO. |
| `hddsynthpro-bb48-drive-v0.33.1.uf2` | The same for the **Olimex RP2350-PICO2-BB48** (the card on SPI). It also runs on the PCB, more slowly. |
| `hddsynthpro-bb48-listen-v0.33.1.uf2` | Listen only, for recording a real drive's bus; never drives a pin. |

## Added

- **Block mode for the hard disk** (READ MULTIPLE, WRITE MULTIPLE and SET MULTIPLE MODE, up to 8 sectors a block). Without it the PC takes an interrupt and checks the drive's status for every sector; with it, once per block. In an Athlon XP PC (PIO 3, the card on SDIO), on the default settings (`early_answers = on`):

  | | Before | With block mode |
  |---|---|---|
  | Reads | 1.72 MB/s | **2.27 MB/s** (+32%) |
  | Writes | 1.23 MB/s | **1.32 MB/s** (+7%) |

  The PC's BIOS decides: this one (an AMIBIOS) turns block mode on by itself, and has no setting for it. With the CD-ROM drive beside the disk, block mode works too.
- **Not with the data lane** (`early_answers = off`): there, blocks made reads 15% slower, so the drive doesn't offer block mode, and the data lane reads as fast as in v0.33.0 (4.12 MB/s in the same PC).

## Fixed

- The bus checker (the `BUSERR` lines on the serial console) could report a wrong sector on an SD image when there was none, after it had skipped some of the bus traffic. More likely with block mode; the data itself was always right.

## Changed

- Some of the firmware that serves each sector now runs from RAM rather than flash, so the drive's speed no longer shifts by up to 10% when unrelated parts of the firmware change.

## Tested

- The Athlon XP PC, on the PCB: the benchmark disk on the data lane and on early answers (with block mode), every sector checked right; MS-DOS from a disk image with Doom from the CD-ROM drive.
- Through a USB IDE adapter: the read and write tests on every way of answering the bus, and an hour's soak: 2.2 GB written and read back, 3.8 million sectors checked on the IDE cable, none wrong.

## Known limits

- Everything in v0.33.0's notes still applies.
- After a PC turns block mode on, the checksum at the end of the drive's identity block is wrong. PCs don't check it as a rule; it will be fixed in the next release.
